# Experiments

This directory contains scripts for the agent-based reconstruction experiments.

Unless a section says otherwise, run commands from the repository root.

## Branched Reconstruction

`branched_reconstruction.py` runs one shared core reconstruction per
natural-language description and then starts comparable feedback branches from
the same `core_final.spectra` incumbent. This is intended for comparing feedback
strategies while holding the initial NL-to-Spectra result fixed.

Dry-run the first three descriptions:

```powershell
python experiments\branched_reconstruction.py `
  --signature-root dataset\signatures `
  --limit 3 `
  --dry-run
```

`cross_repair` is included in the default branch set, so the plain batch command
runs `no_test`, `self_test`, `independent_test`, and `cross_repair`.

By default, the batch only uses NL descriptions whose manifest `model` equals
`ACADEMIC_CLOUD_MODEL` from `.env`. Use `--description-model <model>` to select
another generated-description model, or `--all-description-models` to disable
this filter intentionally.

Completed records are skipped by default when a matching `run_key` already
exists in `experiments/branched_runs/runs.jsonl` with status `success`.
Most `partial_success` records are treated as incomplete and can be retried
without `--force`. The exception is `partial_success` caused by
`branches.independent_test.status == "max_rounds_with_failures"`: this means the
configured independent-test feedback loop budget was exhausted, so the record is
treated as terminal and skipped by default. Use `--force` only when a successful
or terminal record should be recomputed.

The top-level batch `stats` contain mutually exclusive run statuses
(`success`, `partial_success`, `dry_run`, `missing_input`, `skipped`) plus
additional diagnostic counters. In particular,
`partial_success_independent_max_rounds_with_failures` counts the subset of
`partial_success` runs where the `independent_test` branch reached
`--max-feedback-rounds` and still had failing controller tests. Do not add this
counter to the other top-level statuses; it is an overlapping reason count used
for reporting how often independent-test repair exhausted its loop budget.
`partial_success_independent_spec_repair_not_well_separated` counts the subset
where independent-test feedback produced a repaired Spectra file that was not
well-separated and therefore could not be synthesized for another test round.

The batch summary also includes `independent_test_terminal_stats`, a frequency
table over `branches.independent_test.status`. Use
`independent_test_terminal_stats.max_rounds_with_failures` as the direct
evaluation number for "after the configured feedback loops, tests still fail".
Older manifests may contain the legacy independent-test status `completed`; the
batch summary normalizes it to `tests_passed` for evaluation.

If `dataset\signatures` does not contain a matching JSON file, the runner falls
back to the `source_spectra_file` referenced by the NL manifest, extracts the
fixed env/sys signature, and writes it as `signature.json` into the run
directory.

Default time budgets are deliberately generous to avoid biasing branch
comparisons through premature wrapper timeouts:

- `--timeout 7200`: per agent process for every branch.
- `--broker-timeout 1800`: per broker wait in the cross-repair branch.
- `--max-feedback-rounds 3`: shared feedback-round limit for self-test,
  independent-test, and cross-repair branches.

The outer cross-repair wrapper waits longer than the individual cross agents so
that the wrapper does not terminate the incumbent/challenger pair before their
own equal agent budgets expire.

Use `--log-level DEBUG` for more detailed orchestration logs. Logs include run
start/end, core start/end, branch start/end, cross incumbent/challenger
start/end, artifact archiving, timeouts, and manifest locations.

Run the currently implemented branches:

```powershell
python experiments\branched_reconstruction.py --signature-root dataset\signatures --branches no_test self_test independent_test --limit 20 --log-file experiments\branched_runs\batch.log --max-feedback-rounds 3
```

Generated artifacts are written to `experiments/branched_runs/`. The batch
manifest is:

```text
experiments/branched_runs/runs.jsonl
```

Each record is keyed by `core_run_id` and stores branch lineages under
`branches`:

- `core`: generated by `respect-core`; saves `00_initial`,
  `01_after_syntax_repair`, `02_after_unrealizable_repair`,
  `03_after_well_separation_repair`, `final.spectra`,
  `core_context.full.json`, `core_context.test_writer.json`, and
  `repair_log.jsonl`.
- `no_test`: baseline branch; its final Spectra is copied from
  `core_final.spectra`.
- `self_test`: generated by `respect-self-test-from-core`; starts from
  `core_final.spectra` and full core context, writes its own `.rtest` plans, and
  repairs only self-test failures justified by the natural-language
  requirements.
- `independent_test`: uses `respect-test-writer` with filtered context for test
  generation and `respect-spec-tester` with full core context for any
  test-feedback repairs.
- `cross_repair`: uses `cross_repair_from_core.py` to start two broker agents in
  parallel. The incumbent uses `respect-broker-from-core` and starts from
  `core_final.spectra` plus full core context. The challenger uses
  `respect-broker`, starts fresh from only NL plus signature, and keeps its own
  full intermediate Spectra lineage. Both agents may repair based on broker
  feedback, but the primary branch comparison point is the incumbent result
  because it shares the same core start as the other feedback strategies.

Run only the asymmetric cross branch for a generated core:

```powershell
python experiments\branched_reconstruction.py `
  --signature-root dataset\signatures `
  --branches cross_repair `
  --limit 3 `
  --log-file experiments\branched_runs\cross-batch.log `
  --max-feedback-rounds 3
```
