The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs `a`, `r1`, and `r2`, and two system-controlled outputs `g1` and `g2`. 

The environment is assumed to behave in a way that whenever `a` was false in the previous step, it will be true in the current step.

The system guarantees the following behavior: 
- Whenever `r1` is true, the system will eventually respond by setting `g1` to true.
- Whenever `r2` is true, the system will eventually respond by setting `g2` to true.
- If `a` is false, then both `g1` and `g2` must be false.
- At all times, at least one of `g1` or `g2` must be false.

Initially, the system is in a state where it does not expect any requests to be pending. 
The system's behavior can be described as follows: 
- If a request `r1` or `r2` is made, the system will respond by setting the corresponding grant `g1` or `g2` to true, and then return to its initial state once the grant has been given.
- The system ensures that it will infinitely often be in its initial state, where it does not expect any requests to be pending. 
- If a request is made and the corresponding grant is not given, the system will move to a state where it remembers that a request is pending, and it will stay in this state until the grant is given.
