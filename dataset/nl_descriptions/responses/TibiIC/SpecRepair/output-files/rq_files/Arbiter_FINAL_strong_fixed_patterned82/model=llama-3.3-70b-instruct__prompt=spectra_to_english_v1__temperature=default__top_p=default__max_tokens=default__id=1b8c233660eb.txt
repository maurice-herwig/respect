The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs `a`, `r1`, and `r2`, and two system-controlled outputs `g1` and `g2`. 

The environment is assumed to always set `a` to true whenever `g2` is false. 

The system guarantees that whenever `r1` is true, it will eventually set `g1` to true, and whenever `r2` is true, it will eventually set `g2` to true. Additionally, the system ensures that if `a` is false, then both `g1` and `g2` are false. The system also guarantees that at all times, at least one of `g1` or `g2` is false.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as no request is pending or a pending request is granted. If a request is pending and not granted, the system transitions to a state where it is waiting for the request to be granted. Once the request is granted in this waiting state, the system returns to the ready state. The system always eventually returns to the ready state. 

At all times, the system ensures that it is either in the ready state or in the waiting state, and it transitions between these states based on the presence and granting of requests.
