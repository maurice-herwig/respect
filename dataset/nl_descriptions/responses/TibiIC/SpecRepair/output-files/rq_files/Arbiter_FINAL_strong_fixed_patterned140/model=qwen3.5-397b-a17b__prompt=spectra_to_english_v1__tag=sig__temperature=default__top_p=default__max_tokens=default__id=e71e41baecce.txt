

Specification name: Arbiter

Environment variables:
- a: boolean
- r1: boolean
- r2: boolean

System variables:
- g1: boolean
- g2: boolean

The Arbiter system manages two grant outputs, `g1` and `g2`, in response to environment inputs `a`, `r1`, and `r2`.

**Environment Assumptions**
The environment behavior is restricted by the assumption that always, if `a` is true, then `a` is true.

**System Guarantees**
The system must satisfy the following requirements:

1.  **Response to Request 1:** Whenever `r1` is true, the system must eventually ensure that either `a` is false or `g1` is true. The system initializes the monitoring logic for this requirement in a ready state. The system must return to this ready state infinitely often, ensuring that if the condition enters a pending state due to `r1` being true without the response being met, the response is eventually satisfied.
2.  **Response to Request 2:** Whenever `r2` is true, the system must eventually ensure that `g2` is true. This requirement also initializes in a ready state and must visit the ready state infinitely often, guaranteeing that the response is not indefinitely postponed.
3.  **Safety Condition on `a`:** Always, if `a` is false, then either `a` is false or both `g1` and `g2` are false.
4.  **Conflict Avoidance:** Always, at least one of the variables `r2`, `g1`, or `g2` must be false. This prevents `r2`, `g1`, and `g2` from all being true simultaneously.
