The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs `a`, `r1`, and `r2`, and two system-controlled outputs `g1` and `g2`. 

The environment is assumed to always set `a` to true whenever `g1` is false. 

The system must satisfy the following requirements: 
- Whenever `r1` is true, the system must eventually set `g1` to true.
- Whenever `r2` is true, the system must eventually set `g2` to true.
- When `a` is false, the system must keep both `g1` and `g2` false.
- At all times, the system must ensure that at least one of `g1` or `g2` is false.

Initially, the system is in a state where it is ready to respond to requests. 
The system remains in this ready state as long as the corresponding request (`r1` or `r2`) is not present or is present and the corresponding grant (`g1` or `g2`) is also present. 
If a request is present and the corresponding grant is not, the system moves to a state where it is waiting for the grant to be set. 
In this waiting state, the system will move back to the ready state if the grant is set; otherwise, it will remain in the waiting state. 
The system will infinitely often return to the ready state.
