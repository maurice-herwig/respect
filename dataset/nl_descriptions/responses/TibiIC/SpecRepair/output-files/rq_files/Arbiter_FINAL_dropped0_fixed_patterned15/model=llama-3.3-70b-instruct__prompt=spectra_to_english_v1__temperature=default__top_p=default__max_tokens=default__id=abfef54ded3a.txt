The Arbiter system interacts with its environment through four boolean variables: `a`, `r1`, and `r2` are controlled by the environment, while `g1` and `g2` are controlled by the system.

The environment is assumed to behave in such a way that whenever `a` was false in the previous state, it becomes true in the current state.

The system must guarantee the following behavior: 
- Whenever `r1` is true, the system must eventually respond by setting `g1` to true.
- Whenever `r2` is true, the system must eventually respond by setting `g2` to true.
- If `a` is false, then both `g1` and `g2` must be false.
- At all times, either `g1` or `g2` (or both) must be false.

The system's response to requests `r1` and `r2` can be described as follows: 
- Initially, the system is in a state where it is not responding to a request.
- The system remains in this state as long as no request is pending or a request is pending and being responded to.
- If a request is pending and not being responded to, the system moves to a state where it is responding to the request.
- Once the system is responding to a request, it remains in this state until the request is being responded to, at which point it moves back to the initial state.
- The system must return to the initial state infinitely often.
