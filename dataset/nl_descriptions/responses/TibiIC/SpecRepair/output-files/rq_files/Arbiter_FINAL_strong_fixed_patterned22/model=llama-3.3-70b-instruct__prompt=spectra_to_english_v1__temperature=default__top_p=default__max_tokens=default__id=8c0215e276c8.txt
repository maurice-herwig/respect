The Arbiter system interacts with its environment through inputs `a`, `r1`, and `r2`, and produces outputs `g1` and `g2`. The environment controls the values of `a`, `r1`, and `r2`, while the system controls the values of `g1` and `g2`.

The environment is assumed to behave in such a way that whenever `g1` is false, `a` is true.

The system guarantees the following behavior: 
- When `r1` is true, the system will eventually set `g1` to true.
- When `r2` is true, the system will eventually set `g2` to true.
- When `a` is false, both `g1` and `g2` will be false.
- At all times, at least one of `g1` or `g2` will be false.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as no request is pending or a request is pending and being serviced. If a request is pending and not being serviced, the system transitions to a state where it is waiting for the request to be serviced. Once the request is serviced, the system returns to the initial state. The system will infinitely often be in the initial state, ready to respond to new requests.
