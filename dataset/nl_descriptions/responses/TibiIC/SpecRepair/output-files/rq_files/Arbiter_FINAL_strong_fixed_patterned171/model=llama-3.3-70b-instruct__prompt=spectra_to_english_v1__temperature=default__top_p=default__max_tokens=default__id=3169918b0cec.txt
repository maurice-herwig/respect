The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs, `a` and `r1` and `r2`, and two system-controlled outputs, `g1` and `g2`. 

The environment is assumed to behave in such a way that whenever `r1` is true, `a` is also true, and whenever `g2` is true, `a` is also true. 

The system guarantees that whenever `r1` is true, it will eventually respond by setting `g1` to true, and whenever `r2` is true, it will eventually respond by setting `g2` to true. 

Additionally, the system ensures that if `a` is false, then both `g1` and `g2` are false. The system also guarantees that `g1` and `g2` are not both true at the same time.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as no request is pending or a request is pending and being serviced. If a request is pending and not being serviced, the system transitions to a state where it is waiting for the request to be serviced. Once the request is serviced, the system returns to its initial state. The system will infinitely often be in its initial state, ready to respond to new requests.
