The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs `a`, `r1`, and `r2`, and two system-controlled outputs `g1` and `g2`. 

The environment is assumed to behave in such a way that whenever `r1` is true, `a` is also true, and whenever `g2` is true, `a` is true.

The system must guarantee that whenever `r1` is true, it will eventually set `g1` to true, and whenever `r2` is true, it will eventually set `g2` to true. Additionally, the system must ensure that if `a` is false, then both `g1` and `g2` are false. The system must also guarantee that `g1` and `g2` are not both true at the same time.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as the corresponding request is not present or is present and the corresponding grant is given. If a request is present and the corresponding grant is not given, the system moves to a state where it is waiting for the grant to be given. Once the grant is given in this state, the system returns to the ready state. The system must infinitely often return to the ready state.
