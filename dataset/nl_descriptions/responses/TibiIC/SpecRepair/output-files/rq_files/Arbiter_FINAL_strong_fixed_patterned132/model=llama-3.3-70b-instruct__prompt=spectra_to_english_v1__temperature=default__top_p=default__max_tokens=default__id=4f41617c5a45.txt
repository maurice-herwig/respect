The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs `a`, `r1`, and `r2`, and two system-controlled outputs `g1` and `g2`. 

The environment is assumed to always set `a` to true whenever `g2` is false. 

The system must satisfy the following requirements: 
- Whenever `r1` is true, the system must eventually set `g1` to true.
- Whenever `r2` is true, the system must eventually set `g2` to true.
- If `a` is false, then both `g1` and `g2` must be false at all times.
- At all times, either `g1` or `g2` (but not both) must be false.

Initially, the system is in a state where it is ready to respond to requests. 
The system remains in this state as long as no request is pending or a request is pending and being served. 
If a request is pending and not being served, the system transitions to a state where it is waiting for the request to be served. 
Once in this waiting state, the system will remain there until the request is served, at which point it will transition back to the ready state. 
The system will always eventually return to the ready state.
