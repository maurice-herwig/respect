

Specification name: Arbiter

Environment variables:
- a: boolean
- r1: boolean
- r2: boolean

System variables:
- g1: boolean
- g2: boolean

The system acts as an arbiter that manages two grant signals, `g1` and `g2`, in response to two request signals, `r1` and `r2`, subject to an enable signal `a`.

**Assumptions on the Environment**
The environment is assumed to ensure that the signal `a` is true whenever the system sets `g2` to true.

**Guarantees from the System**
The system must satisfy the following requirements:

1.  **Response to Request 1:** The system must respond to request `r1` with grant `g1`. Initially, the system starts in an idle state regarding this relationship. If `r1` is true while `g1` is false, the system enters a pending state and must remain in that state until `g1` becomes true. The system must infinitely often return to the idle state, ensuring that if `r1` is true, `g1` eventually becomes true.

2.  **Response to Request 2:** The system must respond to request `r2` with grant `g2`. Initially, the system starts in an idle state regarding this relationship. If `r2` is true while `g2` is false, the system enters a pending state and must remain in that state until `g2` becomes true. The system must infinitely often return to the idle state, ensuring that if `r2` is true, `g2` eventually becomes true.

3.  **Enable Constraint:** At all times, if the enable signal `a` is false, then both grant signals `g1` and `g2` must be false.

4.  **Mutual Exclusion:** At all times, the grant signals `g1` and `g2` cannot both be true simultaneously. At least one of the two grants must be false.
