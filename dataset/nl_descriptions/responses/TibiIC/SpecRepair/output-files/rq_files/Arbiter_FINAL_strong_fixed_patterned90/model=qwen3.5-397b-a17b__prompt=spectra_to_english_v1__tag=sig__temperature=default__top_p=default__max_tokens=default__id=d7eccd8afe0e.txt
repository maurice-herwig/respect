

Specification name: Arbiter

Environment variables:
- a: boolean
- r1: boolean
- r2: boolean

System variables:
- g1: boolean
- g2: boolean

The Arbiter system manages two grant outputs, `g1` and `g2`, in response to two environment request inputs, `r1` and `r2`, subject to a control signal `a`. The system initializes in a ready state.

Regarding the environment assumptions, it is always the case that if signal `a` is true, then `a` is true.

Regarding the system guarantees, the system must satisfy specific response behaviors for each request. For request `r1`, if `r1` is true while grant `g1` is false, the system enters a pending state. While in this pending state, the system must remain there until either `r1` becomes false or `g1` becomes true. The system must return to the ready state infinitely often. For request `r2`, if `r2` is true while grant `g2` is false, the system enters a pending state. While in this pending state, the system must remain there until `g2` becomes true. The system must return to the ready state infinitely often.

Additionally, the system must adhere to specific safety constraints. Always, if `a` is false, then either `a` is false or both `g1` and `g2` are false. Furthermore, it is never the case that `r2`, `g1`, and `g2` are all true simultaneously.
