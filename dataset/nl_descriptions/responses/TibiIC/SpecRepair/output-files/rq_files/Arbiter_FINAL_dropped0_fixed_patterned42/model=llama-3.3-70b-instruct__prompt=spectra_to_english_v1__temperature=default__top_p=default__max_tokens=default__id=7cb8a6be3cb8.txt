The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs, `a` and `r1` and `r2`, and two system-controlled outputs, `g1` and `g2`. 

The environment is assumed to always set `a` to true when `r1` is true and when `g2` is true. 

The system guarantees that when `r1` is true, it will eventually set `g1` to true, and when `r2` is true, it will eventually set `g2` to true. Additionally, the system ensures that if `a` is false, then both `g1` and `g2` are false. The system also guarantees that `g1` and `g2` are not both true at the same time.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as the corresponding request is not present or is present and the corresponding grant is given. If a request is present and the corresponding grant is not given, the system moves to a state where it is waiting for the grant to be given. Once the grant is given in this waiting state, the system returns to the ready state. The system always eventually returns to the ready state.
