The Arbiter system interacts with its environment through four boolean variables: `a`, `r1`, and `r2` are controlled by the environment, while `g1` and `g2` are controlled by the system. 

The environment is assumed to always set `a` to true whenever `g1` is true. 

The system guarantees that whenever `r1` is true, it will eventually set `g1` to true, and whenever `r2` is true, it will eventually set `g2` to true. Additionally, the system ensures that if `a` is false, then both `g1` and `g2` are false. The system also guarantees that at all times, at least one of `g1` or `g2` is false.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as no request is pending or a request is pending and granted. If a request is pending and not granted, the system transitions to a state where it is waiting for the grant. Once in this waiting state, the system stays there until the grant is given, at which point it returns to the ready state. The system always eventually returns to the ready state.
