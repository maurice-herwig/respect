The Arbiter system interacts with its environment through inputs `a`, `r1`, and `r2`, which are controlled by the environment, and outputs `g1` and `g2`, which are controlled by the system.

The environment is assumed to behave in such a way that whenever `r1` is true, `a` is also true, and if `r1` was false in the previous state, then `a` is true in the current state.

The system guarantees that whenever `r1` is true, `g1` will eventually be true, and whenever `r2` is true, `g2` will eventually be true. Additionally, the system ensures that if `a` is false, then both `g1` and `g2` are false. The system also guarantees that `g1` and `g2` are not both true at the same time.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as the corresponding request is not made or is made and granted. If a request is made and not granted, the system transitions to a state where it is waiting for the grant to be made. Once the grant is made, the system returns to the ready state. The system always eventually returns to the ready state.
