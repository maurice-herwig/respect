The Arbiter system interacts with its environment through four boolean variables: two environment-controlled inputs `a`, `r1`, and `r2`, and two system-controlled outputs `g1` and `g2`. 

The environment is assumed to always set `a` to true whenever `g2` is true and whenever `r1` is true. 

The system must guarantee that whenever `r1` is true, it will eventually set `g1` to true, and whenever `r2` is true, it will eventually set `g2` to true. Additionally, the system must ensure that if `a` is false, then both `g1` and `g2` are false. The system must also guarantee that `g1` and `g2` are not both true at the same time.

Initially, the system is in a state where it is ready to respond to requests. The system remains in this state as long as the corresponding request is not present or is present and granted. If a request is present and not granted, the system moves to a state where it is waiting for the grant. Once in this waiting state, the system will remain there until the grant is given, at which point it returns to the ready state. The system will infinitely often be in the ready state. 

In summary, the system acts as an arbiter, granting requests `r1` and `r2` while ensuring mutual exclusion between `g1` and `g2`, and respecting the environment's control over `a`.
