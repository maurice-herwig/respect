### **System Description: Patrolling Robot**

This specification describes a patrolling robot operating in a bounded 2D grid of size **5×5** (with coordinates ranging from `0` to `4` in both dimensions). The robot’s behavior is defined in terms of its interaction with three designated goal locations, which are provided by the environment.

#### **Inputs and Outputs**
- **Environment-controlled inputs:**
  - `goals`: A fixed list of three goal positions, where each goal is represented as a 2D coordinate pair `(x, y)` with values from `0` to `5`.
- **System-controlled outputs:**
  - `robotX` and `robotY`: The robot’s current position on the grid, constrained to `0` to `4` in both dimensions.
  - `isGoalBlocked`: A set of three boolean flags indicating whether each of the three goals is currently *blocked* (`true`) or *unblocked* (`false`).

#### **System Guarantees**
The robot must satisfy the following requirements:
1. **Liveness for Goal Blocking:**
   - For each of the three goals, the system must *indefinitely often* report the goal as **blocked** (`isGoalBlocked[i] = true`).
   - Independently, for each of the three goals, the system must *indefinitely often* report the goal as **unblocked** (`isGoalBlocked[i] = false`).

   This means that over time, the robot must continuously alternate between blocking and unblocking each goal, ensuring neither state persists indefinitely.

No initial conditions, safety requirements, assumptions about the environment, or explicit next-state rules are specified. The system must focus purely on meeting the liveness conditions for goal blocking and unblocking.
